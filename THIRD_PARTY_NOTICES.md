### jixxed/ed-journal-schemas

- Source: <https://github.com/jixxed/ed-journal-schemas>
- Pinned revision: `33a8f35e81868b168b4bbd647b5e13dbd8de062a`

Kairon's journal event catalogue (`kairon.observation.journal.JournalEventCatalog`
and the records under `src/main/java/kairon/observation/journal/event/`) is pinned
to this revision of the upstream JSON schemas. No upstream file is copied into
this repository and no code generator is used; the Java records are hand-written
transport types and are the source of truth in this project. The pin records
which upstream revision the discriminator set was aligned against.

## Derived reference data

### Silarn/EDMC-BioScan and Silarn/EDMC-ExploData

- Sources: <https://github.com/Silarn/EDMC-BioScan>,
  <https://github.com/Silarn/EDMC-ExploData>
- Pinned revisions: `5f0d2e445a95681bf2e85223f883d5c552a7726b` (BioScan),
  `011ec1d01d17960cb40de6e85139422024f544a8` (ExploData)
- License: **GNU General Public License v2.0** (as stated by both upstream
  repositories)

`config/organic-registry.json` is generated by
`src/test/java/kairon/bio/OrganicRegistryGeneratorTest.java`, which reads the
species tables under `src/bio_scan/bio_data/` and the genus table at
`src/ExploData/explo_data/bio_data/genus.py` at the pinned revisions above.
Taken from them: organic genus and species display names, per-species sample
values in credits, per-genus colony distances, and the star-class and material
tables that say which colour a variant is.

**No upstream file is copied into this repository and no upstream code is
executed or linked.** The generator downloads the pinned revisions on demand,
reads the factual tables out of them, and writes Kairon's own document format.
The generated file is committed so the application runs from a clone; it carries
its provenance in its own `_meta` block. Anyone who considers that file a
derivative work of the upstream tables should treat it as GPL-2.0 material,
separate from the rest of this repository and not relicensed under the PolyForm
Noncommercial License 1.0.0. It is a standalone data file beside the
configuration, is not compiled into the jar, and can be removed and regenerated
locally without touching anything else.

Localised organism names in that file are not upstream material. They are read
out of the Commander's own Elite Dangerous journals by the same generator, or
composed from those readings and verified against them.
